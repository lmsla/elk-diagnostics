# 人工驗證入口

先讀 [`共通準備.md`](./共通準備.md)，再只選一條路線：

| 路線 | 用途 | 手冊 |
|---|---|---|
| A：即時連線 | binary 直接連 ES，驗證 Live 判斷 | [`即時驗證手冊.md`](./即時驗證手冊.md) |
| B：採集包 | 採集端只跑 `collect.sh`，分析端離線產報告 | [`採集包驗證手冊.md`](./採集包驗證手冊.md) |
| 多節點 | ES 8 三節點 M00～M09 | [`多節點驗證手冊.md`](./多節點驗證手冊.md) |

執行順序：先 P00 基準線，再逐案 P01～P16；多節點另跑 M00～M09。每次只保留一個 active case。

## 不可混用

- Live：故障存在時 binary 可直接查詢 ES。
- 採集包：故障存在時只准 `collect.sh`；ES 復原後才可在分析端執行 binary。
- `fault-scenarios.sh` 與 `bundle-case.sh` 只供內部測試，不得用於使用者環境或共用叢集。
- 最新狀態看 [`驗證狀態.md`](./驗證狀態.md)；歷史證據看 [`歷史/驗證紀錄.md`](./歷史/驗證紀錄.md)。
