# 實作進度

目前版本：`0.0.4-mvp`。本頁只記錄目前交付狀態；歷史討論與逐案證據不放在這裡。

## 已實作

- 唯讀 ES API collector、`_health_report` 優先與 raw API 加深。
- Live／採集包共用 analyzer；`check --from-bundle` 完整離線分析。
- JSON、HTML、text 報告；狀態分為 pass／info／warning／critical／skipped／unknown，其中 info 以藍色呈現且不影響 overall。
- 數值型檢查已輸出 `measurements`，HTML 顯示本次觀測值，NDJSON 保留長期趨勢用資料；純狀態項目不假造數值。
- ES 8.4+ 健康檢查、節點 OS／process／filesystem／JVM 快照與 partial coverage 判定。
- HTTPS／Basic Auth／CA、config.yaml、環境變數與 flags 設定來源。
- `collect.sh` 與 API 清單由端點表產生；`make dist` 產出 binary、採集腳本、API 清單與 SBOM。
- 採集包 schema v2 將 ES 原始回應收斂到 `elasticsearch/`，分析端保留 v1 平鋪格式相容。
- 可選的預期 `node.name` 清單可找出採集前已離線節點；Node Context 自動呈現 API 回傳的 IP 與 roles。
- `collect.sh --services` 可選配 Host OS、Kibana、Logstash 子採集器；SSH 僅使用既有 key／agent，原始證據分別寫入 `host/`、`kibana/`、`logstash/`。
- `check --from-bundle` 已接入 Kibana `/api/status`、`/api/task_manager/_health`、`/api/alerting/_health` 健康卡；`/api/stats` 只輸出 `INFO` measurements，不參與故障分級。Kibana 缺檔／403／遮罩回應會顯示 `unknown`，stats 缺失則 `skipped`。

## 正確性邊界

- 實作完成不等於異常分支已真機驗證；狀態以 [`驗證狀態.md`](./驗證狀態.md) 為準。
- ES 報告中的 Node Context 仍只來自 ES API；選配 Host OS 證據尚未接入 analyzer／HTML 診斷卡。
- Logstash 與 Host 目前只完成採集模組，尚未宣稱健康診斷能力；Kibana 已涵蓋 `/api/status`、Task Manager 與 Alerting health，`/api/stats` 仍只作觀測值。
- 需要時間序列、外部叢集或真實負載的項目，不以單次採集包宣稱完成。
