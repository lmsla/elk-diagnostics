## T2｜health_report 失敗降級（目前為整份中止）

現況（實測）：採集包缺 `health_report.json` → `採集失敗` exit 11，整份報告死掉；檔案存在但為 4xx 錯誤 body → 同樣中止。B/C 類 23 個端點的資料完好卻一條都跑不出來。

依 韌性規格 §1（修訂版）實作：

1. **執行期抓取失敗**（連線模式逾時/4xx/5xx；採集包缺檔或錯誤 body）：不中止。A 類診斷（`FromHealthReport` 產出的全部項目）逐條以 `status=unknown` 浮出，summary 註明地基資料缺失；B/C 類照常執行；overall 依 診斷報告規格 §2 收斂、exit code 依 命令列規格 §3（通常 exit 3）。
2. **版本不支援**（es_version < 8.4）：A 類逐條 `skipped`（「ES < 8.4 無 _health_report，本項不適用」）；B/C 照跑、每條附 `version_warning`；報告頂層設 `version_notice`（JSON 欄位新增，HTML 頁首黃條，診斷報告規格 §3 本來就有此欄位規劃）。
3. 仍然 exit 11 的只有：初始連線/認證失敗、採集包目錄不存在/不可讀/缺版本檔（v2 為 `elasticsearch/version.json`，舊 v1 為根目錄 `version.json`）。

**注意**：A 類的 unknown/skipped 列表必須從單一來源導出（不可另建手寫清單——參考 韌性規格 §3 用 analyzer 零值取 id/title 的既有手法，或由 `FromHealthReport` 的項目定義導出），否則新增 A 類診斷時清單會漂移。

**驗收**：
- [ ] `check --from-bundle <fixture 複本，刪掉 health_report.json>` → exit 3；JSON 中所有 A 類 id 都在、status=unknown；B/C 類結果與刪檔前完全一致。
- [ ] health_report.json 為 404 錯誤 body ＋ `_status.txt` 記 404 → 同上行為。
- [ ] 版本檔（v2：`elasticsearch/version.json`；v1：`version.json`）偽造成 7.17.0 → A 類全 skipped、B/C 附 version_warning、JSON 有 `version_notice`、HTML 頁首有黃條。
- [ ] 連線模式：httptest 模擬 `_health_report` 回 500 → 不中止、A 類 unknown（單元測試）。
- [ ] 既有 golden／單元測試全過；healthy fixture 的 golden 輸出不應有任何變化。
