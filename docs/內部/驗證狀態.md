# 驗證狀態

最後更新：2026-08-17。`implemented` 只代表程式與自動化測試完成；`verified` 代表已在真機故障分支確認結果。

## 已完成

- ES 8.14.3／ES 9.0.0：前次 Live 與採集包真機基準線涵蓋 39 個採集端點、52 項診斷結果。
- 現行版本維持 43 個 Elasticsearch 固定端點，另有 4 個選配 Kibana 端點（status、stats、Task Manager、Alerting）；ES parser／analyzer 與 Kibana 健康卡已完成 403／缺檔／格式錯誤自動化回歸，尚未升級為真機 `verified`。
- P00～P16：ES8 Route B 採集包路線已完成；P05 為多因子條件式通過，P11 受 Basic License 限制。
- M00～M09：ES8 三節點 Live／採集包已完成；M08 partial Nodes API 正確回 `unknown`。
- ES-GAP-06 高可用結構、ES-GAP-08 index block：已由 ES8 真機驗證為 `verified`。
- HTTPS、自簽 CA、Basic Auth、採集包離線分析與 HTML 報告：已驗證。
- Host／Kibana／Logstash 子採集器：Shell 語法、假 HTTP 服務與假 SSH 傳輸自動化回歸完成，狀態為 `implemented`。
- Kibana Task Manager、Alerting health 與 Elasticsearch Watcher：已接入採集／分析／HTML，完成自動化 bundle 驗證；真機異常分支仍待驗證。

## 尚未宣稱真機完成

- 真實 indexing pressure、thread pool rejection、queue backlog。
- 真實 JVM heap／CPU／circuit breaker 負載。
- 真實 CCR follower、ML job/datafeed、planned shutdown/voting exclusion 異常。
- ES9 多節點、跨主機與長時間穩定性。
- 採集包的 `--redact`：目前可能含 index、node、host 與 mapping 欄位名稱。
- 新增 ILM policy inventory、SLM repository 關聯、Data stream health、fielddata eviction 四項的 ES8／ES9 Live 與 Route B 真機基準線。
- Host／Kibana／Logstash 子採集器的 Linux／HTTPS／認證／403／timeout 真機證據；Kibana analyzer／HTML 卡目前只有自動化 bundle 驗證，尚未升級為真機 `verified`。

## 判讀規則

- 單次快照不能取代時間序列；高 RAM、CPU、I/O 或 heap 單點值不得直接當根因。
- partial API response 必須是 `unknown`，不能用已回應節點推論全叢集正常。
- P／M 案例的造壓結果只代表測試配方成立，不代表該故障涵蓋所有生產變體。
