# 多節點驗證手冊

只供 ES 8 三節點內部測試。M 系列使用既有 `fault-scenarios.sh`、`bundle-case.sh` 與 `collect.sh`，沒有第二套腳本。

## 1. 啟動環境

```bash
./dev/phase0/podman-test-env.sh up-multinode
./dev/phase0/podman-test-env.sh up-multinode-kibana   # 需要畫面觀察時才啟用
./dev/phase0/podman-test-env.sh status
```

ES URL 為 `https://localhost:9218`；Kibana URL 為 `https://localhost:5611`。接著依 [`共通準備.md`](./共通準備.md) 設定環境，並將：

```bash
export ES_URL='https://localhost:9218'
```

## 2. 基準線與案例

```bash
fault M00 verify
```

必須看到 `multi_baseline=clean`。M00 未通過時停止。

Route A（Live）以 M03 為例：

```bash
fault M03 trigger
fault M03 verify
"$TOOL_BIN" check --host "$ES_URL" --username "$ES_USER" --ca-cert "$CA_CERT" \
  --output html --output-file "$EVIDENCE_ROOT/M03-fault/live-report.html"
fault M03 restore
fault M00 verify
```

Route B（Bundle）：

```bash
bundle_case M03 trigger
bundle_case M03 collect
bundle_case M03 restore
bundle_case M03 collect-post
```

再依 [`採集包驗證手冊.md`](./採集包驗證手冊.md) 在分析端執行 `--from-bundle`。

一次完成可用 `bundle_case M03 run`，但人工截圖應使用分段模式。

## 3. 注意事項

- M03～M08 會建立臨時 helper node；restore 後確認容器已移除。
- M08 的 partial Nodes API 應判定為 `unknown`，不是 pass。
- M07 是偶數 master-eligible 的結構性風險，不代表已重現選舉抖動。
- 同一 Podman VM 不等於跨主機或真實 availability zone；ES9 多節點與真實負載另列未驗證。

完成後：

```bash
fault M00 verify
rm -f "${ES_PASSWORD_FILE:-}"
unset ES_URL ES_USER ES_PASSWORD_FILE CA_CERT FAULT_CMD BUNDLE_CASE_CMD COLLECT_SH EVIDENCE_ROOT
trap - EXIT
```
