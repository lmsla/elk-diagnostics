# 診斷資料採集包（Bundle）驗證手冊

只驗證使用者路線：採集端執行 shell／`collect.sh`，分析端再用 binary。不可在採集端執行 binary。

前置環境依 [`共通準備.md`](./共通準備.md)；案例說明依 [`案例矩陣.md`](./案例矩陣.md)。

## 1. 採集階段

先採集 P00：

```bash
bundle_case P00 collect
```

分段驗證一案：

```bash
bundle_case P01 trigger
bundle_case P01 collect
bundle_case P01 restore
bundle_case P01 collect-post   # 選配：復原後基準線
```

`trigger` 後 ES 保持故障；`collect` 會再次驗證故障仍在，輸出到
`$EVIDENCE_ROOT/P01-fault/bundle`。復原前可將截圖放在
`$EVIDENCE_ROOT/P01-fault/screenshots/`，不要放進採集包。

一次完成可用：

```bash
bundle_case P01 run
```

`run` 固定執行 `trigger → collect → restore → collect-post`；需要人工截圖時使用分段模式。

中斷時只執行對應案例的 restore：

```bash
bundle_case P01 restore
"$FAULT_CMD" baseline verify
```

完成採集後確認：

```bash
"$FAULT_CMD" baseline verify
echo "export EVIDENCE_ROOT='$EVIDENCE_ROOT'"
```

## 2. 分析階段

開新的分析 Terminal，只設定採集端輸出的 `EVIDENCE_ROOT`。不設定 ES URL、帳號、CA。

```bash
export TOOL_BIN="$PWD/elk-diagnostics"
export REPORT_ROOT="$PWD/reports/$(basename "$EVIDENCE_ROOT")"
mkdir -p "$REPORT_ROOT"

"$TOOL_BIN" check \
  --from-bundle "$EVIDENCE_ROOT/P01-fault/bundle" \
  --output html \
  --output-file "$REPORT_ROOT/P01-fault.html"
```

同一採集包可再產生 JSON 或文字報告：

```bash
"$TOOL_BIN" check --from-bundle "$EVIDENCE_ROOT/P01-fault/bundle" --output json \
  --output-file "$REPORT_ROOT/P01-fault.json"
```

`--from-bundle` 全程不連線 ES；HTML 是離線單檔。exit code `1`／`2` 代表報告含 warning／critical，不等於產報失敗。

## 3. 驗證閘門

- 新版故障採集包（schema v2）必須含 `elasticsearch/version.json`、`_manifest.json`、`_status.txt`；舊 v1 平鋪格式僅保留作相容性回歸。
- 故障報告依 [`案例矩陣.md`](./案例矩陣.md) 比對主要診斷，不鎖死 pass 總數。
- 復原後採集包應回到乾淨基準線；若未恢復，不得進下一案。
- 採集包可能包含 index、node、IP、hostname 與 mapping 欄位名稱；外傳前須依資料治理流程審閱。
