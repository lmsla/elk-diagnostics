# 報表摘要修正清單

本文件用來記錄報表摘要後續細修項目。只有雙方討論並確認的內容才列入；每項完成修改與驗證後再勾選。

## 已確認、待實作

- [x] **Frozen tier 顯示規則**
  - 採集結果沒有 Frozen tier 或有效 Frozen 容量為 0 時，摘要不顯示 Frozen 相關欄位。
  - 不在摘要中單獨顯示 `cluster.max_shards_per_node.frozen = 3000`，避免被誤解為叢集目前可用容量。
  - 有 Frozen tier 時，才另外顯示 Frozen shard 的使用量與有效容量。

- [x] **Shard 容量摘要不可顯示錯誤的 `2865 / 0`**
  - 混合 data role（例如同時具備 `data_hot` 與 `data_frozen`）時，不得因角色判讀錯誤把一般 shard 容量算成 `0`。
  - 優先使用 Elasticsearch `_health_report/shards_capacity` 的有效容量資料。
  - 若無法可靠判定容量，顯示 `—` 或 `unknown`，不可將未知狀態當成 `0`。

- [x] **摘要狀態卡片調整**
  - 移除「通過率」卡片。
  - 保留既有的「通過／警告／嚴重」統計。
  - 新增「資訊／略過／未知」三項統計。

- [x] **服務狀態卡片顯示版本**
  - Elasticsearch、Kibana、Logstash 的版本都放在各卡片標題下方的第一列。
  - 版本列不與卡片標題合併。
  - 未採集的服務顯示「未採集」；多個 instance 版本不一致時顯示「多版本」或列出版本集合。

- [x] **叢集狀態摘要的未採集服務提示**
  - 摘要版面維持固定，不因沒有 Kibana 或 Logstash 資料而留下空白區塊或跑版。
  - 未包含 Kibana 資料時，顯示「本次健檢未採集 Kibana 資料。」。
  - 未包含 Logstash 資料時，顯示「本次健檢未採集 Logstash 資料。」。
  - 「未採集」須與「採集失敗／不可用／未知」分開呈現，不得混用。

- [x] **時間顯示統一使用台灣時間**
  - 報表中的資料採集時間與報告產生時間，顯示為 `Asia/Taipei`（`UTC+08:00`）。
  - 原始資料與內部時間仍保留 UTC，不修改來源時間。
  - 不依賴執行主機的系統時區，避免不同環境產生不一致的顯示結果。

- [ ] **時間顯示格式簡化**
  - 保留台灣時間的實際日期與時間值。
  - 移除畫面上的 `（Asia/Taipei，UTC+08:00）` 括號說明，不改變時區轉換邏輯。

- [x] **ES 節點盤點以 IP 為主要識別值**
  - 預期節點清單改採 `node.name|IP` 格式；比對時以 IP 為主要鍵。
  - `node.name` 僅作顯示與輔助資訊，允許不同節點使用相同名稱。
  - IP 需依 Nodes API 回傳值正規化後比對。
  - IP 變更時，現場需重新產生預期節點清單；不得把舊 IP 靜默視為同一節點。

- [x] **重複 node name 不得造成節點磁碟顯示 `—`**
  - `_cat/nodes` 的磁碟資料改以 Node ID／IP 對應，不以重複的 `node.name` 作唯一鍵。
  - 舊版 bundle 缺少 Node ID／IP 時，回退使用同一節點 filesystem 的總容量與可用容量計算磁碟率。
  - 重複名稱的節點仍須各自顯示正確磁碟使用率；只有缺少可靠識別或原始資料時才顯示 `—`。
  - 補上重複 node name、不同 IP 的測試案例。
